# 接口联调对接

当前端页面或组件可能还在使用 mock 数据，需要按照接口文档接入真实后端接口时使用这个 skill。

## 流程

1. 先检查现有模式，再开始改代码。
   - 阅读目标组件、相邻 API 模块、共享类型和已有测试。
   - 阅读接口文档，提取请求方法、URL、query/body 参数、响应嵌套、分页结构、鉴权或 header 说明。
   - 确认当前 UI 实际消费的数据结构。
   - 以当前 UI 的字段、列、section、tab 和交互为边界；接口返回更多字段时只做类型保留、内部映射或缺口说明，不新增页面展示字段。

2. 划清最小接口边界。
   - 请求函数放到项目已有的同业务域 API 目录。
   - 请求和响应类型放到项目已有的共享类型目录。
   - API 层尽量保留后端原始响应结构；在靠近 UI 的位置或独立 mapper 中做字段适配。

3. 字段映射不直观时，先测 mapper。
   - 抽一个纯函数负责把后端行数据转成 UI 行数据。
   - 覆盖字段完整、字段缺失兜底、列表顺序等关键行为。
   - 覆盖“不会新增 UI 字段/列/section/tab”的结构断言，确保 mapper 只填充页面原有字段。
   - 如果项目有测试运行器，先运行并确认测试在实现前失败。

4. 窄范围接入 UI。
   - 只替换用户要求的 mock 模块，除非明确要求扩大范围。
   - 不因为接口文档包含额外字段就扩展 UI；新增展示字段、表格列、信息分组、tab 或交互必须由用户明确要求。
   - 接口要求业务主键时，优先使用稳定业务字段，不使用偶然的路由 id。
   - 按项目附近 UI 习惯补 loading、empty 和失败处理。
   - 路由或查询条件变化可能触发并发请求时，防止旧响应覆盖新数据。

5. 在代码里写清后端合同 TODO。
   - TODO 放在受影响的具体代码路径附近。
   - 字段缺失、字段语义不明、时间格式、排序规则、分页策略、响应嵌套、权限或 header 不一致，都要写 TODO。
   - TODO 要能直接拿去和后端沟通。

6. 校验并交付。
   - 运行聚焦测试和改动文件 lint。
   - 条件允许时运行 build 或 typecheck。
   - 如果全量检查被既有问题挡住，记录命令和第一个无关失败点。
   - 最终说明接口地址和参数、改动文件、代码 TODO、校验结果，以及需要后端确认的问题。
